# Webhooks

> Populi API2 model. Source: https://populi.co/api/models/webhooks.html. Docs version: 2026-10-05 17:15:39 PST. Generated by `populi-docs`; do not edit.

Webhooks are automations that send information to your outside applications when certain events happen in Populi.

## Setting up webhooks

Account Administrators can create webhooks in Populi under Account → Webhooks. Each webhook listens for one event, and when that event occurs Populi sends an HTTP request (GET or POST, configurable per webhook) to the URL you provide.

In production, URLs entered with `http://` are automatically upgraded to `https://` before the request is sent. Webhooks do not fire from sandbox instances unless they are explicitly enabled in the instance settings.

If your server returns a non-2xx response, Populi retries the delivery up to four times at increasingly distant intervals. After five consecutive failures, the webhook action is paused so you can fix the issue before it resumes.

## The webhook payload

Every webhook request contains a JSON body with the following envelope, followed by a `data` object whose contents depend on the specific event.

```json
{
  "id": "a1b2c3d4e5f6...",
  "event": "person_created",
  "created_at": "2026-09-17T12:00:00+00:00",
  "sandbox": false,
  "api_version": "2026-07-13",
  "data": { ... }
}
```

The `sandbox` field is `true` when the request comes from a validation or demo instance, and `false` for live production data. The payload may also include a legacy `test_mode` field that mirrors `sandbox`; it is deprecated and will be removed in the future.

## Verifying webhook authenticity

Each webhook request includes two headers you can use to verify it came from Populi:

- `Populi-RSA-SHA256-Signature` — a hex-encoded RSA-SHA256 signature of the raw JSON request body
- `Populi-RSA-Public-Key-Fingerprint` — the fingerprint of the public key used to verify the signature

Verifying the signature is optional, but recommended if your webhook endpoint is publicly accessible.
